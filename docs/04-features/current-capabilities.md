# قابلیت‌های فعلی

این فهرست «وجود UI» را از «عملیاتی بودن end-to-end» جدا می‌کند.

## عمومی و بازاریابی

| قابلیت | وضعیت | توضیح |
|---|---|---|
| صفحه اصلی جدید | عملیاتی | CTA مشاوره و ثبت شماره در دیتابیس |
| صفحه فروشنده هوشمند | عملیاتی | معرفی، CTA دمو و مسیر تبدیل |
| ثبت سرنخ مشاوره/دمو | عملیاتی | `ConsultationLead` و مشاهده مدیریتی |
| صفحات سایر سرویس‌ها | نمایشی/آینده | مطابق اولویت آمادگی سرویس‌ها تکمیل شوند |

## پنل کاربر

| قابلیت | وضعیت |
|---|---|
| ورود OTP و session | عملیاتی با driver محلی |
| داشبورد و کسب‌وکار | عملیاتی |
| مشاهده سرویس‌های تخصیص‌یافته | عملیاتی |
| صورتحساب، سفارش و اشتراک | بنیاد مدیریتی آماده؛ درگاه واقعی ندارد |
| اعلان‌ها | عملیاتی داخل برنامه |
| تیکت و پیام پشتیبانی | عملیاتی |
| راه‌اندازی واقعی سرویس در n8n | نیازمند worker و قرارداد اتصال |

## پنل مدیریت

| حوزه | قابلیت‌ها | وضعیت |
|---|---|---|
| مشتریان | کاربران، ویرایش، وضعیت، کسب‌وکارها، اعضا، تیکت | عملیاتی |
| دسترسی | نقش‌ها و permissionهای قابل مدیریت | عملیاتی |
| محصول | کاتالوگ، ویرایش سرویس، تخصیص به کسب‌وکار | عملیاتی |
| فروش | پلن، اشتراک، سفارش، پرداخت | مدل و UI عملیاتی؛ gateway ندارد |
| عملیات | connector، provisioning job، retry | بنیاد آماده؛ executor ندارد |
| ارتباط | اعلان‌ها و سرنخ‌ها | عملیاتی داخل برنامه |
| کنترل | Audit Log و وضعیت سیستم | عملیاتی؛ متن meta قدیمی نیازمند اصلاح |

## قابلیت‌های ناقص مهم

1. ارسال OTP production؛
2. اتصال end-to-end فروشنده هوشمند به n8n و بله؛
3. درگاه پرداخت، webhook امن و reconciliation واقعی provider؛
4. worker provisioning و callback؛
5. سیاست نهایی قیمت‌گذاری؛
6. تست موبایل، keyboard و screen reader؛
7. مانیتورینگ، alert و runbook production؛
8. تکمیل صفحه و قرارداد سرویس‌های بعدی.

## تعریف «کامل»

قابلیت فقط وقتی کامل است که UI، validation، API، permission، tenant isolation، persistence، audit، حالت‌های loading/error/empty، تست و مستند آن آماده باشند. برای اتصال بیرونی، timeout، retry، idempotency، observability و runbook نیز لازم است.
