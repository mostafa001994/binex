# پشتیبان‌گیری و بازیابی

## چه چیزهایی پشتیبان می‌شوند

- dump منطقی دیتابیس `binix`؛
- فایل‌های schema و migration همراه Git؛
- تنظیمات غیرمحرمانه استقرار؛
- secretها در password manager/secret manager، نه داخل backup کد.

## قواعد backup

- نام فایل دارای timestamp و محیط باشد.
- خروجی صفر بایت یا dump بدون جدول معتبر نیست.
- backup در دیسک جدا یا فضای رمزگذاری‌شده نگهداری شود.
- سیاست retention و دسترسی محدود تعریف شود.
- حداقل ماهانه restore آزمایشی انجام شود؛ داشتن dump بدون آزمون restore کافی نیست.

## قبل از تغییر پرریسک

از دیتابیس dump بگیرید، اندازه و exit code را کنترل کنید، migration مورد انتظار را ثبت کنید و مسیر rollback را مشخص کنید.

## بازیابی

بازیابی ابتدا در دیتابیس خالی و غیرproduction آزمایش می‌شود. سپس migration status، تعداد رکوردهای کلیدی، ورود، health endpoint و عملیات نمونه بررسی می‌شوند. overwrite دیتابیس فعال بدون تأیید صریح و backup تازه ممنوع است.
