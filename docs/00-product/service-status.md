# وضعیت سرویس‌ها و قابلیت‌های محصول

این سند بین «وجود صفحه»، «وجود مدل مدیریتی» و «آمادگی واقعی سرویس» تفاوت می‌گذارد.

## سرویس‌ها

| اولویت | سرویس | وضعیت محصول | وضعیت کاتالوگ seed | توضیح |
|---:|---|---|---|---|
| 1 | فروشنده هوشمند | آماده‌ترین سرویس؛ صفحه فروش و درخواست دمو کامل | `AVAILABLE` | اتصال واقعی n8n و قرارداد اجرای workflow باید جداگانه تکمیل و مستند شود. |
| 2 | رزرو نوبت | آماده عرضه و دریافت درخواست راه‌اندازی | `AVAILABLE` | صفحه بازاریابی و فرم اختصاصی کامل است؛ قرارداد اتصال آن به n8n پس از ثبت فرایند اجرایی تکمیل می‌شود. |
| 3 | ماژول‌های BI | آماده عرضه و دریافت درخواست راه‌اندازی؛ ماژول نخست فروش | `AVAILABLE` | منبع فعلی Excel و نمایش داشبورد داخل Binix است؛ قرارداد دریافت و به‌روزرسانی داده پس از ثبت فرایند اجرایی تکمیل می‌شود. |
| 4 | تحلیل اکسل | صفحه بازاریابی و دریافت درخواست آزمایشی کامل؛ موتور تحلیل هنوز متصل نیست | `COMING_SOON` | فایل در فرم بازاریابی دریافت نمی‌شود؛ جریان production، سیاست نگهداری فایل و موتور پردازش باید تکمیل شوند. |

ترتیب بالا تصمیم محصول است. `src/constants/services-config.ts` فقط تنظیمات صفحات تخصصی است و در بعضی موارد وضعیت قدیمی دارد؛ منبع کاتالوگ runtime، دیتابیس و API کاتالوگ است.

## قابلیت‌های پلتفرم

| قابلیت | وضعیت | شاهد اصلی |
|---|---|---|
| ثبت درخواست مشاوره و دمو | عملیاتی | `ConsultationLead` و `/api/leads` |
| پنل مدیریت درخواست‌ها | عملیاتی | `/admin/leads` |
| احراز هویت OTP در توسعه | عملیاتی با driver Mock | `auth-service.ts` و `otp-provider.ts` |
| ارسال OTP واقعی | برنامه‌ریزی‌شده | driver `sms` خطای not configured می‌دهد |
| کاربران و کسب‌وکارها | عملیاتی | Prisma + APIهای admin/business |
| RBAC قابل مدیریت | عملیاتی | `AccessRole` و `AccessRolePermission` |
| کاتالوگ پویا | عملیاتی | `ServiceDefinition` |
| credential فروشنده هوشمند | بنیاد آماده | توکن‌ها رمزنگاری و مدیریت می‌شوند؛ اجرای سرویس جداست |
| پلن و اشتراک | بنیاد آماده | مدل و پنل مدیریت وجود دارد؛ قیمت نهایی نشده |
| سفارش و پرداخت | بنیاد آماده | ledger و reconciliation وجود دارد؛ درگاه واقعی وجود ندارد |
| صف راه‌اندازی | بنیاد آماده | job و retry وجود دارد؛ worker dispatch n8n کامل نیست |
| اتصال n8n | بنیاد آماده | endpoint و secret رمزنگاری می‌شوند؛ executor در کد فعلی دیده نمی‌شود |
| تیکت پشتیبانی | عملیاتی | تیکت، پیام، ارجاع، اعلان و SLA |
| اعلان‌ها | عملیاتی | اعلان کاربر و هشدار عملیاتی |
| Audit Log | عملیاتی | ثبت actor، request ID، IP و metadata پاک‌سازی‌شده |

## ناسازگاری‌های شناخته‌شده

- `src/server/system/system-service.ts` در payload متا هنوز `admin: planned` و `database: not-connected` برمی‌گرداند؛ این متن با وضعیت فعلی کد سازگار نیست.
- `src/constants/services-config.ts` برای بعضی سرویس‌ها availability متفاوت از seed دارد؛ این فایل نباید منبع فهرست عمومی باشد.
- `compose.yaml` به‌تنهایی Mock است؛ اتصال database فقط با overlay فایل `compose.postgres.yaml` فعال می‌شود.
